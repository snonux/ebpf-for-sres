Containers

One kernel, many namespaces

BPF sees the node

All containers share the node's kernel. A probe fires for every process in every container.

Filter by namespace or cgroup

Match the container in the kernel: cgroup == cgroupid(...) in bpftrace, the mount namespace inode in C.

PIDs are relative

PID 1 in the pod is PID 48213 on the node. Report the PID the pod owner recognises.

Running the tracer in a container

Privileged, or CAP_BPF + CAP_PERFMON. It needs /sys/kernel/btf.

Distroless targets

A distroless app image has no shell, no package manager, no bpftrace. Do not rebuild it: bring one static binary in a debug container next to it.

Before Kubernetes, the container basics. BPF runs in the node's kernel and has no idea what a container is, so a probe sees everything on the node. To trace one container you filter on what a container is made of: its mount namespace, PID namespace or cgroup. Running a BPF tool inside a container needs privileges and access to the kernel's BTF and tracefs, which are often missing in a container's view of /sys. And modern app images are distroless, often Chainguard: no shell, no package manager, nothing. That is the setup for the workflow on the next slide.
