Build once: what gets in the way

Every host runs a different kernel

Functions move

A kprobe attaches to a symbol of one kernel build. do_sys_open became do_sys_openat2 in 5.6; functions get inlined and vanish.

→ use tracepoints

Structs change

A field is read at a byte offset, and offsets differ between versions and configs. RHEL 9 widened trace_event_raw_sys_enter by 8 bytes: such programs fail the verifier on Rocky 9.

→ CO-RE, next

Features arrive

Bounded loops 5.3, ring buffer 5.8. RHEL backports, so uname -r lies: Rocky 9's 5.14 has most of 6.x BPF.

→ bpftool feature probe

If we compile ahead of time, the binary meets kernels we have never seen. Three things differ. Function names change, so kprobes fail to attach; tracepoints are the stable answer, which is why our tools use them. Struct layouts change, so a hard-coded offset reads garbage. A real example we hit with ior and in these examples: RHEL 9 backports a patch that makes the BTF type trace_event_raw_sys_enter 8 bytes wider than what a syscall tracepoint program really gets, so the verifier rejects such programs with EACCES on stock Rocky 9; every example here uses struct syscall_trace_enter instead. And features arrive over time, but Red Hat backports a lot into 5.14, so probe for features rather than comparing version numbers. Compiling on each host, as bpftrace does, sidesteps the struct problem. To build once we need another answer for it, and that is CO-RE.
