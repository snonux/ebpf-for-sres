The LLM closes the loop

Every event carries the syscall, duration and file. Together with the source code that is enough to name the culprit.

The closing demo. ior is a complete I/O syscall tracer built on exactly the ideas from today: libbpfgo, syscall tracepoints, CO-RE and a static binary built on Rocky 9. We use the same Kubernetes workflow as with storeiops: upload the static ior binary into the debug container, trace the app's process for a minute and write every file syscall with its duration and file name as CSV, keep the /store lines, and copy the file out. Then hand the trace and the application's source code to an LLM and ask which code paths produce the pattern. Check which PID ior expects in the debug container before the talk: the PID inside the pod, or the node PID from a node debug container. Prepare a recorded trace as a fallback.
