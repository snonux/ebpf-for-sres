Helpers

The only kernel functions a program may call

Just a few examples. The kernel offers more than 200 helpers, and each program type may use a subset. Full list: man bpf-helpers

Typical in a tracer: observe only

// who is running, and when
u64 id  = bpf_get_current_pid_tgid();
u64 now = bpf_ktime_get_ns();
bpf_get_current_comm(&ev->comm, sizeof(ev->comm));

// copy a file name out of the process
bpf_probe_read_user_str(&ev->path, sizeof(ev->path), name);

// remember something between two events
bpf_map_update_elem(&start, &id, &now, BPF_ANY);
u64 *t0 = bpf_map_lookup_elem(&start, &id);
bpf_map_delete_elem(&start, &id);

// send an event to user space
ev = bpf_ringbuf_reserve(&events, sizeof(*ev), 0);
bpf_ringbuf_submit(ev, 0);

Some helpers change things

bpf_skb_store_bytes()
bpf_redirect()		Rewrite or redirect network packets. Load balancers and Cilium build on this.
bpf_override_return()Make a kernel function return an error without running it: fault injection.
bpf_probe_write_user()Write into a process's memory. Man page: “a risk of crashing the system and running programs”.

Everything we build today only observes: it reads, counts and reports. It changes nothing on the system.

A BPF program cannot call arbitrary kernel functions. It can only call helpers, a fixed list the kernel exposes, and each program type gets its own subset. There are more than two hundred of them; man bpf-helpers lists them all. This slide is only here so you have seen what they look like. On the left is what a typical I/O tracer calls, and all of it only observes: bpf_get_current_pid_tgid tells us which process and thread is running, bpf_ktime_get_ns gives a timestamp for latencies, bpf_get_current_comm the process name. bpf_probe_read_user_str safely copies a string such as a file name out of the process. The map helpers store a value when a syscall starts, look it up when it returns and delete it again. And reserve plus submit sends one event through the ring buffer to user space. They are ordinary C function calls; nothing exotic. But BPF is not read-only by nature. Networking programs rewrite and redirect packets; that is how load balancers and Cilium work. bpf_override_return makes a kernel function return an error without running it, for fault injection, and only on functions the kernel marks as safe for that. bpf_probe_write_user writes into a process's memory; the man page itself warns of a risk of crashing the system and running programs. A program can never write arbitrary kernel memory, but with these helpers a verified program can still break a service. Everything in this talk observes only: it reads, counts and reports, and that is why it is comfortable to run on production.
