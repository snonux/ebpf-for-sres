An introduction for SREs and developers

eBPF: safe little programs
inside the Linux kernel

From bpftrace one-liners to tools you ship: one static Go binary with the BPF program inside, built once with CO-RE, running on any modern kernel, and quick to write with an LLM. Every example runs on Rocky Linux 9.9.

Paul Buetow

$ sudo bpftrace -e 'tracepoint:syscalls:sys_enter_openat { @[comm] = count(); }'

About 45 minutes including three demos, questions at the end. The plan: what BPF is and why it is safe on production boxes; bpftrace, just enough to read a one-liner; why compiling on the production host is the wrong default; and then the direction I want to steer you in: small tools as one static Go binary with the BPF program embedded, compiled once with CO-RE and running on any kernel that has BTF. Ready before the incident, nothing to install on the host. We use one in a Kubernetes debug container, and end with how LLMs make these tools quick to build and their output quick to read. The command at the bottom counts file opens per process name; we will come back to it.
