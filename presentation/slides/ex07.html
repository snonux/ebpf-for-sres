Example 07: uprobes

DNS latency of any program, no code change

uprobe:libc:getaddrinfo    { @start[tid] = nsecs; @host[tid] = arg0; }
uretprobe:libc:getaddrinfo /@start[tid]/ {
    printf("%-16s %6d us %s\n", comm, (nsecs - @start[tid]) / 1000, str(@host[tid]));
}

Every glibc user

curl, ssh, Python, Java with the system resolver: one probe on libc covers them all.

Costly hook

A uprobe is a trap into the kernel: microseconds, not nanoseconds. Fine for getaddrinfo, not for malloc.

examples/07-dns-latency-uprobe/ · dnslat.bt · Go (SEC("uprobe/libc.so.6:getaddrinfo"))

uprobes do for user space what kprobes do for the kernel. Here we hook getaddrinfo in libc, so every program that resolves names through glibc shows up with its lookup latency, which is a classic hidden cause of slow requests. The Go version uses libbpf's automatic attach: the section name says libc.so.6:getaddrinfo and libbpf finds the library in /usr/lib64 on Rocky. Be careful with uprobes on hot functions: each hit is a trap into the kernel and costs microseconds, so probing malloc in a busy service is a bad idea.
