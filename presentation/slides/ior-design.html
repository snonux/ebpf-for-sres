Lessons from ior

Design choices worth copying

ChoiceWhy
Tracepoints, not kprobesA stable interface that survives kernel upgrades
A ring buffer mapOne shared buffer for all CPUs, events in order, no extra copy
Filter in the kernelUnwanted events are discarded before they cost anything downstream
Stateless BPF, smart GoSmall programs pass the verifier easily; analysis stays flexible
vmlinux.h and BTFOne binary runs on any kernel that ships BTF type info
Generate the handlers117 syscalls without copy-paste mistakes
If you ever build your own eBPF tool, these are good defaults. The ring buffer (BPF_MAP_TYPE_RINGBUF, kernel 5.8 and later) replaced the older per-CPU perf buffer for most use cases. Keeping the BPF side dumb and doing analysis in a normal language is a pattern you will see in many production tools.
