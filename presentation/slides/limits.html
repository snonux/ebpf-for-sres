The sandbox is small on purpose, and it is worth knowing the numbers, because hitting them is the most common surprise. Program size: originally 4096 instructions. Since kernel 5.2 there is no fixed size; instead the verifier analyses up to one million instructions across all paths and then rejects the program as too complex. Loops: none at first, bounded loops since 5.3, and a bpf_loop helper since 5.17 for longer ones. The stack is 512 bytes, which is why larger buffers live in maps; the newest kernels allow up to 2 KiB on x86-64 and arm64. Function calls can nest 8 deep and tail calls chain 33 times. For sending events to user space, the ring buffer arrived in 5.8: you choose its size, a power of two, and when it is full events are dropped, never the traced process blocked. Without root, the old 4096-instruction limit still applies. The trend is clear: every kernel generation raises the limits. On Rocky 9 the 5.14 kernel has everything up to 5.14, and Red Hat backports newer features, so test rather than assume. The practical rule stays the same: keep the kernel half small, filter and count there, and do everything else in user space.
