Safety

Why it is safe enough for production

The verifier

Checks every program before loading: no out-of-bounds reads, no unchecked pointers, no endless loops.

Helpers only

Programs call a fixed set of kernel helper functions, not arbitrary kernel code.

Small and bounded

Size and complexity limits; each run finishes quickly and cannot block.

Privileged

Loading tracing programs needs root, or CAP_BPF plus CAP_PERFMON.

Safe does not mean free: the overhead grows with how often your event fires.

Compare this with a kernel module: a bug in a module can panic the box, a bug in a BPF program is rejected at load time. The verifier is conservative, which is why writing BPF C sometimes feels like arguing with it. The one thing the verifier does not protect you from is cost: a cheap program attached to an event that fires a million times per second is still a million runs per second.
