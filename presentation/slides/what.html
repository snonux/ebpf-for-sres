What is eBPF

Small programs the kernel runs when something happens

Think of it as JavaScript for the kernel: you attach sandboxed code to an event instead of patching the kernel, loading a module or rebooting.

Event-driven

Runs on a syscall, a kernel or app function, a network packet or a timer.

Verified

The kernel checks every program before it runs, so it cannot crash or hang the machine.

JIT-compiled

Bytecode is translated to native machine code, so it runs at near-native speed.

The name once meant "extended Berkeley Packet Filter". Today eBPF and BPF are used interchangeably.

eBPF started as a packet filter (tcpdump uses classic BPF) and grew into a general in-kernel virtual machine. Three properties matter: it is event-driven, the verifier makes it safe, and the JIT makes it fast. That combination is what makes it usable on production machines, unlike loading a custom kernel module.
