What is BPF

Small programs the kernel runs when something happens

Think of it as JavaScript for the kernel: attach sandboxed code to an event instead of patching the kernel, loading a module or rebooting.

Event-driven

Runs on a syscall, a kernel or app function, a network packet or a timer.

Verified

The kernel checks every program before it runs: it cannot crash or hang the machine.

JIT-compiled

Bytecode becomes native machine code: near-native speed.

The name

1992Berkeley Packet Filter: a tiny VM in BSD that filters packets for tcpdump
2014Linux 3.18, extended BPF: 64-bit registers, maps, helpers, hooks far beyond networking
TodayKernel docs and tools say BPF and mean eBPF. IETF standard: RFC 9669
WindowseBPF for Windows: an open-source port in progress, own hooks. This talk: Linux
What it is, and the name in one go. Think of it as JavaScript for the kernel: instead of patching the kernel, loading a module or rebooting, you attach a small sandboxed program to an event. Three properties matter: it is event-driven, the verifier makes it safe, and the JIT makes it fast. That combination is what makes it usable on production machines. On the name: BPF was invented at Berkeley Lab in 1992 to filter packets cheaply, and tcpdump still compiles its filters to classic BPF. In 2014 Alexei Starovoitov's extended BPF landed in Linux 3.18 and turned it into a general-purpose in-kernel VM. Nobody writes classic BPF any more, so BPF and eBPF mean the same thing today, and the instruction set is now an IETF standard. Windows has a port in progress with different hooks, so everything in this talk is Linux, and the examples target Rocky Linux 9.9.
