Writing BPF

Pseudo C in the kernel, any language in user space

Kernel side: compiled to BPF bytecode

LanguageHow
Restricted Cclang -target bpf. No libc, 512-byte stack, every pointer checked: "pseudo C"
RustAya compiles Rust to BPF; libbpf-rs loads C objects from Rust
bpftraceawk-like scripts, compiled to BPF on the fly

User side: loads it and reads the results

LanguageLibrary
Clibbpf (the reference loader)
Golibbpfgo (wraps libbpf, ior uses it), cilium/ebpf
RustAya, libbpf-rs
Pythonbcc (compiles C at runtime on each host)

In this talk: bpftrace for one-liners, restricted C + Go (libbpfgo) for tools.

Whatever you write, it ends up as the same BPF bytecode. On the kernel side that is C with a lot of restrictions, which is why people call it pseudo C: no standard library, a tiny stack, no unbounded loops, and the verifier has to be able to prove every memory access is safe. Rust is an option through Aya. bpftrace generates the bytecode for you. On the user side any language that can make the bpf() syscall works; libbpf in C is the reference, and libbpfgo wraps it for Go, which is what ior and our examples use. bcc is the older approach: Python with embedded C that is compiled on every host at startup.
