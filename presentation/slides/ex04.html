Example 04

How big are the reads?

$ sudo bpftrace -e 'tracepoint:syscalls:sys_exit_read /args.ret > 0/
                     { @bytes = hist(args.ret); }'

Output from the Go version (same format)

@bytes:
[256, 512)      534 |@@@@@@@@@@@@@@@                      |
[512, 1K)      1543 |@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@|
[8K, 16K)      1752 |@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@|
[64K, 128K)     219 |@@@@@                                  |

/args.ret > 0/ is a filter: only successful reads that returned data. Lots of tiny reads is a classic sign of missing buffering. In C, hist() is an array map of 64 log2 slots.

examples/04-read-size-hist/ · readsize.bt · readsize.stp · Go

A histogram instead of a counter. The filter between slashes runs in the kernel, so failed reads never touch the map. In the C and Go version the histogram is an array map with 64 slots and a bounded loop computes the log2 bucket, which the verifier accepts because the loop has a fixed upper bound. The Go program prints it in bpftrace's format, which is what you see here.
