storeiops, kernel side

Two filters, then count

const volatile u64 target_mntns;  // set from Go
const volatile u32 target_dev;

static int on_enter(long fd, u32 op) {
  struct task_struct *t = (void *)bpf_get_current_task();
  if (BPF_CORE_READ(t, nsproxy, mnt_ns, ns.inum)
        != target_mntns)
    return 0;                      // other container
  if (fd_dev(t, fd) != target_dev)
    return 0;                      // not on /store
  // remember start time for this thread
}
static u32 fd_dev(struct task_struct *t, long fd) {
  // fd → struct file → inode → superblock
  struct file **fds = BPF_CORE_READ(t, files, fdt, fd);
  bpf_core_read(&f, sizeof(f), &fds[fd]);
  return BPF_CORE_READ(f, f_inode, i_sb, s_dev);
}
ENTER(read, IO_READ)  EXIT(read)     // + pread, readv,
ENTER(close, IO_CLOSE) EXIT(close)   // write…, fsync…

Stable hooks

Syscall tracepoints only: no kprobes that break on the next node image.

Filter first

Every process on the node hits the probe. Two compares later, only the app's /store I/O is left.

CO-RE everywhere

task → nsproxy → mnt_ns, task → files → fdt, file → inode → sb: all relocated at load.

Aggregate

Per (PID, op): count, bytes, errors, total and max latency. No event stream, no drops.

Medium depth on the featured example. Two global variables come from user space: the app's mount namespace and the device number of its /store file system. On every read, write, open, fsync or close, we first check the mount namespace, which throws away everything outside the app container in a few instructions. Then we turn the file descriptor into the file system it lives on, by following the task's file table to the struct file, its inode and the superblock, all with CO-RE reads. Only if both match do we record a start time; the exit handler computes latency and adds to a per-PID, per-operation stats entry. No ring buffer, so nothing can be dropped and the cost stays low even for a busy app.
