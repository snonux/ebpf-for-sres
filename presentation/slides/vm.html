This is where the program actually lives. The loader in user space hands bytecode to the kernel with the bpf() syscall. Inside the kernel it lands in a small virtual machine, a sandbox. The verifier checks the program first; only then does the JIT turn it into native machine code. The next slides look at the verifier and the hooks in turn. Hooks such as uprobes in your app, kprobes, tracepoints, network and scheduler events trigger it. The program can only touch the outside world in two ways: helpers, a fixed list of kernel functions it is allowed to call, and maps, memory it shares with user space. Maps hold totals and state, like counters and histograms; a ring buffer map streams one record per event, which is how you share content such as file names or request details rather than just numbers. Your tool reads maps with the same bpf() syscall and the ring buffer through mmap, so events are not copied. That sandbox is why you can run this on production hosts. Think of it in two phases: once, at load time, compile, load, verify, JIT and attach; then every time the event fires, the program runs, writes into a map or the ring buffer, and your tool reads it.
