This is where the program actually lives. The loader in user space hands bytecode to the kernel with the bpf() syscall. Inside the kernel it lands in a small virtual machine: eleven registers, a 512-byte stack, no unbounded loops. The verifier walks every path first; only then does the JIT turn it into native machine code. Hooks such as uprobes in your app, kprobes, tracepoints, network and scheduler events trigger it. The program can only touch the outside world in two ways: helpers, a fixed list of kernel functions it is allowed to call, and maps, memory it shares with user space. Your tool reads those maps with the same bpf() syscall. That sandbox is why you can run this on production hosts.
