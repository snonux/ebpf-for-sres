What makes build-once possible

BTF: the kernel describes its own types

What

BTF = BPF Type Format. A compact description of every struct and field of the running kernel, with its byte offset.

Where

/sys/kernel/btf/vmlinux
On by default in Rocky and RHEL 9. No kernel-devel, no debuginfo.

Why it matters

A loader can look a field up by name on the kernel it is running on.

$ bpftool btf dump file /sys/kernel/btf/vmlinux | grep -A250 "STRUCT 'task_struct'"
[114] STRUCT 'task_struct' size=3264 vlen=248
    'pid'          type_id=68  bits_offset=10112
    'real_parent'  type_id=115 bits_offset=10240    // = byte 1280

On this kernel a process's parent pointer sits at byte 1280. On Rocky 9.9 it is at byte 2760. Keep those two numbers in mind.

To build once and run everywhere we need one more ingredient: the kernel has to tell us where things are. That is BTF, the BPF Type Format: a compact description of every type in the running kernel, every struct and every field with its offset. It is exposed at /sys/kernel/btf/vmlinux, and Rocky and RHEL 9 ship it on by default, so you need neither kernel-devel nor debuginfo packages. You can read it yourself with bpftool: here is task_struct, the kernel's process structure, and its field real_parent at bit offset 10240, which is byte 1280. On Rocky 9.9 the same field is at byte 2760. The same file is what bpftrace reads when you write curtask->real_parent, and bpftool turns it into vmlinux.h, the one header our BPF C files include.
