Example 11: one tool, two halves

BPF C in the kernel, Go in user space

count_writes.bpf.c: kernel

struct {
  __uint(type, BPF_MAP_TYPE_HASH);
  __uint(max_entries, 10240);
  __type(key, u32);    // PID
  __type(value, u64);  // write() calls
} counts SEC(".maps");

SEC("tracepoint/syscalls/sys_enter_write")
int count_writes(void *ctx) {
  u32 pid = bpf_get_current_pid_tgid() >> 32;
  u64 one = 1, *n =
      bpf_map_lookup_elem(&counts, &pid);
  if (n) __sync_fetch_and_add(n, 1);
  else bpf_map_update_elem(&counts, &pid,
                           &one, BPF_ANY);
  return 0;
}

main.go: user space, libbpfgo

//go:embed count_writes.bpf.o
var bpfObj []byte

m, _ := bpf.NewModuleFromBuffer(bpfObj, "cw")
m.BPFLoadObject()     // verifier runs here
m.AttachPrograms()    // per SEC() name
defer m.Close()

<-ctx.Done()           // Ctrl-C or -duration
counts, _ := m.GetMap("counts")
for it := counts.Iterator(); it.Next(); {
  k := it.Key()
  v, _ := counts.GetValue(unsafe.Pointer(&k[0]))
  fmt.Println(pid(k), comm(pid(k)), u64(v))
}

This is the anatomy of every Go example in the repository, and of ior. On the left the kernel half: a map declaration and a function with a SEC name that says where to attach it. On the right the user half with libbpfgo: embed the compiled object into the binary, open it, load it (this is when the verifier runs, and where you get its log if it refuses), attach every program to the hook its section names, wait, and read the map with an iterator. The same object is also loaded by a 60-line C program in the same directory, so you can compare libbpf in C with libbpfgo directly. The Go code on the slide is lightly trimmed of error handling.
