Maps

How the kernel and your tool share data

A BPF program cannot print to your terminal. It writes into maps, which user space reads. Summarising in the kernel means only a small result crosses into user space.

Map typeGood for
HashPer-PID or per-file counters, start timestamps
ArrayFixed slots: configuration, histogram buckets
Per-CPU hash or arrayLock-free counters on very hot paths
LRU hashTracking many keys without running out of room
Ring bufferStreaming individual events to user space (what ior does)

In bpftrace, every @variable is a map.

Maps are the only way data moves between the BPF program and user space, and between separate runs of the program. The key design decision in any eBPF tool is how much to aggregate in the kernel. Counting in a hash map is very cheap; shipping every event through a ring buffer, as ior does, gives maximum detail but costs more per event.
