bpftrace: one line, one question

Every program has this shape

probe /filter/ { action }

Count: who opens files?

$ sudo bpftrace -e 'tracepoint:syscalls:sys_enter_openat
    { @[comm] = count(); }'

Stream: who opens which file?

$ sudo bpftrace -e 'tracepoint:syscalls:sys_enter_openat {
    printf("%-16s %s\n", comm, str(args.filename)); }'

nginx           /var/www/html/index.html
python3         /etc/ssl/certs/ca-certificates.crt

Two patterns: count in the kernel, or stream each event. For everything else: bpftrace.org (language reference, one-liner tutorial) and man bpftrace.

bpftrace is awk for kernel events, and this one slide is all the bpftrace syntax we need today. Every program is a probe, an optional filter and an action. The first one-liner is the command from the cover: on every openat syscall, bump a counter keyed by process name; bpftrace prints the map when you press Ctrl-C. The second one prints a line per event instead, which is opensnoop in one line: comm is the process name, args.filename is the syscall argument and str() copies the string out safely. Those are the two patterns everything else builds on: aggregate in the kernel, or stream events to user space. I am deliberately not going deeper: the bpftrace site has the full language reference and a one-liner tutorial, and the man page is good. On Rocky 9.9 it is one dnf install. Syntax note: versions before 0.20 write args->filename.
