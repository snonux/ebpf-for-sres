The name

BPF, eBPF, and now just BPF

1992: BPF

The Berkeley Packet Filter: a tiny virtual machine in the BSD kernel that decides which packets tcpdump gets to see.

2014: eBPF

Linux 3.18, "extended" BPF: 64-bit registers, maps, helper calls, and hooks far beyond networking.

Today: BPF

Classic BPF is cBPF; the kernel docs and tools say BPF and mean eBPF. Both names are fine. The instruction set is an IETF standard (RFC 9669).

Where it runs

Linux is home. Microsoft's eBPF for Windows is an open-source port in progress, with its own hooks: today's tools and examples are Linux-only.

Quick history so the names stop being confusing. BPF was invented at Berkeley Lab in 1992 to filter packets cheaply in the kernel, and tcpdump still compiles its filter expressions to classic BPF. In 2014 Alexei Starovoitov's extended BPF landed in Linux 3.18 and turned it into a general-purpose in-kernel VM. Nobody writes classic BPF any more, so BPF and eBPF mean the same thing today. Windows has a port in progress (eBPF for Windows), but the hooks there are different, so everything in this talk is Linux, and the examples target Rocky Linux 9.9.
