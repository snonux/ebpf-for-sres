The SRE question

"What is this process doing right now, and why is it slow?"

ToolWhat you getThe catch
Logs and metricsWhat the app chose to reportBlind to anything nobody instrumented
straceEvery syscall of one processptrace stops the process on each syscall: it can slow it down many times over
perfCPU samples and hardware countersGreat for "busy on CPU", weaker for "waiting on something"
eBPFCustom answers from almost any kernel eventLow overhead, summarised in the kernel, no restart or code change
Start with the question every on-call engineer asks. Classic tools each have a blind spot. strace is the one most people know, but it works via ptrace and pauses the target on every syscall, which is why you should be careful running it on a busy production process. eBPF lets you ask new questions of a running system without restarting anything.
