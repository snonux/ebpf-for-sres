How big are the reads?

Re-implements this bpftrace

tracepoint:syscalls:sys_exit_read /args.ret > 0/ { @bytes = hist(args.ret); }

SEC("tracepoint/syscalls/sys_exit_read")
int read_size(struct syscall_trace_exit *ctx) {
  if (ctx->ret <= 0) return 0;   // the /filter/
  u32 slot = 0; u64 v = ctx->ret;
  while (v && slot < 63) {        // bounded loop
    v >>= 1; slot++; }
  u64 *n = bpf_map_lookup_elem(&hist, &slot);
  if (n) __sync_fetch_and_add(n, 1);
  return 0;
}

./readsize, sandbox run

hist() in C is an array map of 64 log2 slots. Go reads all 64 and prints them like bpftrace.

examples/04-read-size-hist/ · readsize.bt · readsize.bpf.c + main.go

A histogram instead of a counter. bpftrace's hist() becomes an array map with 64 slots in C, and a bounded loop computes the log2 bucket; the verifier accepts the loop because it has a fixed upper bound. The filter runs in the kernel, so failed reads never touch the map. Note the struct syscall_trace_exit: that is the Rocky 9 fix from the kernel-versions slide. Lots of tiny reads is the classic sign of missing buffering.
