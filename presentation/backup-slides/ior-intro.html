How ior uses eBPF

I/O Riot NG traces 117 I/O-related syscalls, measures how long each one took and the gaps between them, and shows it live as a terminal dashboard and flame graphs.

Go, C and libbpfgo · github.com/snonux/ior

Now the grown-up version of our Go examples. ior is a Linux-only, BPF-based I/O syscall tracer: sudo ior opens a process picker, and once you pick a PID you get a live dashboard with syscalls, files, processes, latency and flame graphs. Everything we saw so far appears in it: syscall tracepoints, libbpfgo, a ring buffer, a PID filter set through const volatile globals before loading, and the entry/exit pairing from example 05, done in Go instead of a map. The examples in this repo are deliberately the KISS subset of ior: no generated probes, no TUI.
