Every bpftrace @variable is a map. Maps can be pinned in /sys/fs/bpf to outlive the loader.

Every BPF tool is two programs: the BPF object in the kernel and a loader in user space. They never call each other; they share maps. A map is a kernel data structure with a file descriptor: the BPF side updates it with helpers, user space reads it with the bpf() syscall. Aggregating in a hash map is cheapest because only the summary crosses over. A ring buffer streams individual events when you need them all, at a higher cost. Global variables go the other way: user space writes them before loading, and because they are const volatile, the verifier treats them as constants. All of our Go examples use exactly these calls.
