tracepoint:syscalls:sys_enter_read                { @start[tid] = nsecs; }
tracepoint:syscalls:sys_exit_read /@start[tid]/ { @usecs = hist((nsecs - @start[tid]) / 1000);

int read_enter(void *ctx) {
  u32 tid = (u32)bpf_get_current_pid_tgid();
  u64 ts = bpf_ktime_get_ns();
  bpf_map_update_elem(&start, &tid, &ts, BPF_ANY);
  return 0;
}

The pattern to remember

On entry, store a timestamp keyed by thread ID. On return, subtract it and delete the entry. ior does this for 117 syscalls.

examples/05-read-latency/ · readlat.bt · readlat.stp · readlat.bpf.c + main.go

This is the core pattern of latency tracing. One map holds a timestamp per thread, the exit program computes the delta, bumps a histogram slot and deletes the entry so the map does not grow. The Go side is the same as example 04: wait, read 64 slots, print. Keep this pattern in mind: ior does exactly this for over a hundred syscalls, except that it pairs the events in user space.
