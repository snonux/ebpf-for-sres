The same idea in C with libbpf

#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10240);
    __type(key, u32);    // PID
    __type(value, u64);  // write() calls
} counts SEC(".maps");
SEC("tracepoint/syscalls/sys_enter_write")
int count_writes(void *ctx) {
    u32 pid = bpf_get_current_pid_tgid() >> 32;
    u64 one = 1, *n = bpf_map_lookup_elem(&counts, &pid);
    if (n) __sync_fetch_and_add(n, 1);
    else   bpf_map_update_elem(&counts, &pid, &one, BPF_ANY);
    return 0;
}
char LICENSE[] SEC("license") = "GPL";

1. Kernel types, from BTF

bpftool btf dump file /sys/kernel/btf/vmlinux format c > vmlinux.h

2. Compile to BPF bytecode

clang -O2 -g -target bpf -c count.bpf.c -o count.bpf.o

3. Load and attach

from a small loader: libbpf in C, or libbpfgo in Go as ior does

4. Inspect the map

sudo bpftool map dump name counts

This is the bpftrace @[pid] = count() idea written by hand. The struct with SEC(".maps") declares a hash map from PID to a counter. SEC("tracepoint/...") tells the loader where to attach the function. The program looks the PID up, increments atomically if present, inserts 1 otherwise. vmlinux.h is generated from the running kernel's BTF type info, which is what lets one compiled object run on many kernel versions (CO-RE). ior's BPF code follows exactly this structure.
