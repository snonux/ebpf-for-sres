DTrace is a tracer with its own D language. eBPF is a general VM in the kernel: tracing, plus networking, security and scheduling. Brendan Gregg: “eBPF does more.”

A question I always get: what about the other Unixes? eBPF is Linux only. FreeBSD and macOS only have classic BPF, the Berkeley Packet Filter that tcpdump uses, and Solaris and illumos have no eBPF either; FreeBSD had an eBPF port as a 2018 work in progress, but it is not something you can use there. What those systems have is DTrace, which Sun built for Solaris 10 in 2005 and which inspired much of what bpftrace looks like. FreeBSD ships it in base with full kernel support. macOS ships dtrace and dtruss, but System Integrity Protection blocks most of it unless you partly disable SIP from recovery mode, and it cannot trace Rosetta processes. DTrace is a capable tracer, but it is only a tracer; eBPF is a general in-kernel virtual machine that also does networking, security and scheduling. Gregg summed it up in 2018 as: eBPF does more. Windows, for completeness, has its own eBPF port from Microsoft.
