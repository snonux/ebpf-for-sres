Example 05

Latency: time from entry to return

$ sudo bpftrace -e '
tracepoint:syscalls:sys_enter_read              { @start[tid] = nsecs; }
tracepoint:syscalls:sys_exit_read /@start[tid]/ {
    @usecs = hist((nsecs - @start[tid]) / 1000);
    delete(@start[tid]);
}'

The pattern to remember

On entry, store a timestamp keyed by thread ID. On return, subtract it. ior does this for 117 syscalls, pairing the events in Go.

This is the core pattern of latency tracing. The @start map holds one timestamp per thread; the exit tracepoint computes the delta and feeds a histogram in microseconds, then deletes the entry so the map does not grow. Keep this pattern in mind: it is exactly what ior does, with the same syscall tracepoints, except ior does the pairing in user space rather than in a BPF map.
